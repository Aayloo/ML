# ML 实验质量规范

这份清单是本仓库的最低实验标准。Notebook 以教学为主，但结论必须清楚区分“演示现象”和“可泛化证据”。

## 1. 问题与数据

- [ ] 明确任务类型：回归、二分类、多分类、聚类或排序。
- [ ] 定义特征、标签、预测时点和可用信息边界。
- [ ] 记录数据来源、版本、许可、下载方式和本地文件路径。
- [ ] 检查缺失值、重复行、异常值、类别比例和标签质量。
- [ ] 先建立一个简单 baseline（Dummy、均值、上一期值或线性模型）。

## 2. 切分与防泄漏

- [ ] 普通独立同分布数据使用分层 train/validation/test 切分。
- [ ] 时间序列保持时间顺序，使用 expanding/rolling walk-forward 验证，不随机打乱。
- [ ] 标准化、缺失值填补、编码、PCA 和特征选择只在训练折上拟合。
- [ ] 预处理与模型放进同一个 `Pipeline` 或 `ColumnTransformer`。
- [ ] 最终测试集只用于一次最终评价，不用于选择模型、阈值或特征。
- [ ] 目标构造可以使用未来标签，但特征不能读取预测时点之后的信息。

## 3. 指标与诊断

- [ ] 指标与任务和业务代价匹配：不要在类别不平衡时只报 Accuracy。
- [ ] 分类至少同时查看 Precision、Recall、F1、ROC-AUC 或 PR-AUC，并检查混淆矩阵。
- [ ] 回归至少同时查看 MAE、RMSE 和 R²，并检查残差或预测-真实图。
- [ ] 聚类同时报告目标函数/轮廓系数等内部指标，并说明外部标签仅用于解释还是用于评价。
- [ ] 记录均值与波动（如 CV mean ± std），不要只展示一次随机切分的最高分。
- [ ] 查看错误样本、边界样本和失败模式，说明模型为什么会错。

## 4. 可复现性

- [ ] 固定 NumPy、模型和交叉验证中的随机种子。
- [ ] 记录 Python 版本和关键依赖最低版本；需要下载的数据提供脚本或本地副本说明。
- [ ] Notebook 从头到尾按顺序运行，不依赖隐藏的旧变量或手工执行顺序。
- [ ] 输出中的数字来自实际运行结果，不手工编造或只保留最好的一次结果。

## 5. 金融与回测专项

- [ ] 明确预测时点、持有期、调仓频率、交易成本、滑点和基准。
- [ ] 特征、标签、训练窗口、验证窗口和最终测试窗口按时间隔离。
- [ ] 模型选择区间与最终回测评价区间分离，不能用最终回测结果挑模型后再称为无偏结果。
- [ ] 报告年化收益、波动率、夏普、最大回撤、换手或胜率，并说明计算口径。
- [ ] 回测是教学演示，不构成投资建议；历史样本结果不代表未来收益。

## 6. 结果表达

- [ ] 把探索性可视化和严格预测评估分开命名。
- [ ] 说明数据规模、时间范围、测试样本量和已知限制。
- [ ] 不把“模型跑通”写成“模型有效”，不把相关性写成因果关系。
- [ ] 每个章节末尾保留一句可验证的结论和一个下一步改进方向。
