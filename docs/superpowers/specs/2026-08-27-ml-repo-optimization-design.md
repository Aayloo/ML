# ML 仓库学习路径与实验规范优化设计

## 目标

把仓库从“按章节堆放 Notebook 的个人学习记录”提升为“别人可以快速理解、按路径学习、可复现实验并能识别边界的公开 ML 学习仓库”。本次优化优先改善入口、路线图和高风险实验方法，不重写已经完成的全部 Notebook。

## 现状与问题

1. `00_机器学习模型路线图.ipynb` 内容有价值，但没有代码输出，作为 GitHub 首屏导航不如 Markdown 文档直观。
2. README 的学习路径使用长文本箭头，章节数量和分组存在歧义：`00–17` 是 18 个 Notebook，其中 `00` 是路线图，`01–17` 是 17 个课程/项目章节。
3. 整套 Notebook 在一次提交中加入，因此目录页显示相同的 `Initial commit`；这是历史信息，不应通过重写历史解决。
4. 14 章在全时间范围上计算目标截尾分位数，可能把未来分布信息带入训练期。
5. 16 章用同一段样本外结果选择最优模型并展示其回测，模型选择和最终评价没有完全分离。
6. 部分 PCA、标准化和聚类用于探索性可视化，若不加标签，读者容易把它们误解成严格的预测评估流程。

## 设计决策

### 1. 文档入口

- 新增 `docs/learning-roadmap.md` 作为学习路线的可点击、可维护主文档。
- 使用 GitHub 原生 Mermaid 绘制一张路线图，节点直接链接到对应 Notebook；主线按“基础 → 经典监督学习 → 无监督 → 集成 → 工程流程 → 数据形态分支”组织。
- README 首屏只保留简洁总览，并链接到路线图、质量规范和章节表，避免把完整课程说明复制两遍。
- 保留 `00_机器学习模型路线图.ipynb`，将其定位为详细学习指南，并在开头链接 Markdown 路线图；它不再承担唯一导航职责。

### 2. ML 实验规范

- 新增 `docs/ml-quality-checklist.md`，固定本项目的最低标准：问题定义、baseline、数据溯源、切分策略、Pipeline、防止数据泄漏、指标与业务目标匹配、错误分析、随机性控制和结果边界。
- 规范按普通 i.i.d. 数据、时间序列和量化回测分别说明验证方式，不把时间序列随机切分与普通交叉验证混用。
- Notebook 中只做与当前章节直接相关的修正，不抽象出新的 Python 包或引入额外框架。

### 3. 高风险实验修正

- 14 章：目标截尾边界只使用训练窗口可获得的信息，或移除截尾并在说明中保留极端值处理边界；所有样本外结果仍使用滚动训练窗口。
- 16 章：将模型选择阶段和最终回测阶段明确分开，至少保留一个不参与模型排序的最终评估区间；回测结果同时报告基准、交易成本、调仓频率和样本区间。
- 13、15、16 章：把全量拟合的 PCA/标准化/聚类明确标记为探索性分析；用于预测性能的转换器只在训练数据上拟合，并在代码中保留 `fit`/`transform` 的边界。
- 17 章：交叉验证使用固定随机种子的分层折叠，确保每次运行的比较可复现。

## 文件范围

### 新增

- `docs/learning-roadmap.md`：路线图、学习分支、章节链接和通过标准。
- `docs/ml-quality-checklist.md`：项目级 ML 实验与数据治理规范。

### 修改

- `README.md`：首屏导航、准确的章节计数、章节链接、运行说明、数据与实验边界。
- `00_机器学习模型路线图.ipynb`：修正章节计数和主线描述，加入 Markdown 路线图入口。
- `14_金融回归/14_btc_return_regression.ipynb`：消除全样本目标截尾造成的未来信息使用，并补充滚动验证说明。
- `16_量化ML/16_quant_ml_factor.ipynb`：区分模型选择和最终回测，补充量化实验边界与基准说明。
- `13_综合项目/13_ml_all_models.ipynb`、`15_图像分类/15_fashion_mnist.ipynb`：为探索性全量变换与严格预测流程加注释/说明，避免评估语义混淆。
- `17_文本分类/17_text_classification.ipynb`：固定分层交叉验证的 shuffle 和 random state。

## 不在本次范围内

- 不删除已有 Notebook，不迁移现有章节目录，不重写所有提交历史。
- 不把 Notebook 全部拆成 Python 包，不加入 MLflow、DVC 或 CI 平台等新的工程基础设施。
- 不宣称金融结果可直接用于投资，不把演示数据当作生产数据或实时数据。

## 验收标准

1. README 能在首屏找到路线图、章节入口、安装运行方式和实验规范。
2. 路线图的每个章节节点都能链接到仓库内实际存在的 Notebook。
3. README、路线图和 `00` Notebook 对 Notebook 数量、课程章节数量和项目分支的说法一致。
4. 18 个 Notebook 都能通过 JSON 解析；下载脚本能通过 Python 编译检查。
5. 14、16 章的代码和文字不再把全样本未来信息或同一最终评价集上的模型选择描述成无偏估计。
6. 选定的高风险 Notebook 能在当前依赖环境执行，或在缺少依赖/数据时给出明确、可操作的失败原因。
7. Git 历史保持原样，新增提交使用清晰的 Conventional Commit 类型，不强制推送重写历史。
